# Yomikae server

Local HTTP server that takes a raw Japanese manga page and returns the same page in English. It detects text blocks, OCRs them, translates the whole page in one LLM call, inpaints the original text away, and typesets English inside each bubble. The browser extension in `../extension/` is its only client. The HTTP contract is `../docs/contract.md`.

## Run

On a fresh clone, follow [Install](#install) first. Then, from this directory (`server/`):

```sh
.venv/bin/uvicorn yomikae.app:app --host 127.0.0.1 --port 7878
```

Startup loads all models and warms them, which takes about 6 s once weights are on disk. The first start on a new machine also downloads the manga-ocr weights (about 30 s) and pays a one-time cuDNN autotune (about 12 s). The server answers on `http://127.0.0.1:7878`. Check it with `curl http://127.0.0.1:7878/v1/health`.

The default translator is LM Studio with `google/gemma-4-12b`. Start it first:

```sh
lms get google/gemma-4-12b
lms load google/gemma-4-12b -y
lms server start
```

`lms` is LM Studio's command line tool. Any OpenAI-compatible endpoint and model work instead; see `YOMIKAE_OPENAI_BASE_URL` and `YOMIKAE_OPENAI_MODEL` below.

## Configuration

All configuration is environment variables. There is no settings UI.

| Variable | Default | Meaning |
| --- | --- | --- |
| `YOMIKAE_TRANSLATOR` | `openai` | `openai` (any OpenAI-compatible endpoint), `google_free` (keyless Google endpoint, no context), or `fake` (tests). |
| `YOMIKAE_OPENAI_BASE_URL` | `http://localhost:1234/v1` | LM Studio, Ollama (`http://localhost:11434/v1`), or Gemini's compat endpoint. |
| `YOMIKAE_OPENAI_MODEL` | `google/gemma-4-12b` | Model name sent to the endpoint. Any OpenAI-compatible model works. |
| `YOMIKAE_OPENAI_API_KEY` | `lm-studio` | Bearer token. |
| `YOMIKAE_OPENAI_REASONING_EFFORT` | `none` | Sent as `reasoning_effort`. `none` stops Gemma from thinking first, which cut a call from 7.6 s to 0.7 s. Set it empty to omit the field for endpoints that reject it. |
| `YOMIKAE_CASE` | `upper` | `upper` sets dialogue in all caps in Anime Ace 2 when `fonts/animeace2_reg.ttf` exists, else in Shantell Sans Medium (the closest open-licensed match), and shouts in Bangers. `mixed` keeps the translation's casing in Comic Neue Regular, with shouts in Comic Neue Bold. The translation in the JSON response keeps its casing either way. |
| `YOMIKAE_DIALOGUE_FONT` | unset | Path to any font file to set dialogue in, overriding the face `YOMIKAE_CASE` picks. |
| `YOMIKAE_SHOUT_FONT` | unset | Path to any font file to set shouts in. |
| `YOMIKAE_BUBBLE_MODEL` | `manga109-bubble-seg.onnx` | File name in `models/` of the Ultralytics YOLO segmentation export that finds speech balloons. |
| `YOMIKAE_BALLOON_DETECT` | off | Set to `1` to OCR balloons the segmenter finds with no detected text block. It recovers tiny hand-drawn balloons but also reads some hand-drawn SFX as dialogue. |
| `YOMIKAE_DETECT_DEVICE` | `cuda` | Where the text detector and the balloon segmenter run: `cuda` or `cpu`. `YOMIKAE_LOW_VRAM=1` and a machine without CUDA always use `cpu`. On the CPU they take about 0.95 s per page (about 0.8 s for the detector's two passes, 0.15 s for the segmenter on a Ryzen 7 7800X3D) and hold no GPU memory. Their ONNX Runtime CPU sessions run without a memory arena, which keeps about 1.6 GB out of RAM between pages for about 70 ms more per page. With `cuda`, each session's CUDA arena grows only by what it asks for and stops at 1.5 GB. |
| `YOMIKAE_LOW_VRAM` | off | Set to `1` to run every model on the CPU, so the server holds no GPU memory at all. OCR takes about 0.6 to 0.75 s for a page with 4 bubbles, and LaMa about 0.9 s per region it fills, so a page with 11 such regions took 12 s in all. |
| `YOMIKAE_CACHE_DIR` | `server/cache` | Where `v<PIPELINE_VERSION>/<page_id>/result.json` and the rendered page (`rendered.webp`, `rendered.jpg` past WebP's 16383 px limit, or `rendered.png` past JPEG's 65535 px limit) go. `pipeline.PIPELINE_VERSION` goes up whenever rendering or translation output changes, so older renders are never served. The server deletes older version folders at startup. `DELETE /v1/cache` clears the current one. |
| `YOMIKAE_CACHE_MAX_BYTES` | `2147483648` (2 GiB) | Size cap for the current version's cache. Past it, the least recently read pages are evicted after each new page. |
| `YOMIKAE_REPORTS_DIR` | `~/.local/share/yomikae/reports` | Where page reports from the extension's **Report** button are saved: the original page, the render, and the reader's marks. |
| `YOMIKAE_EXTENSION_ID` | any | Accept requests with a `chrome-extension://` origin only from these extension ids, comma-separated. Requests from web pages are always refused; see [contract.md](../docs/contract.md#who-may-call-the-server). |

## Install

From `server/` in a fresh clone, create the venv and install the server with [uv](https://docs.astral.sh/uv/):

```sh
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python torch --index-url https://download.pytorch.org/whl/cu128
uv pip install --python .venv/bin/python -e '.[test]'
```

`pydensecrf` is built from source from a pinned git commit, so the install needs `git` and a C++ compiler. Add the `bench` extra, as in `-e '.[test,bench]'`, to install `sacrebleu` for `tools/translation_bench.py`.

The fonts are committed under `fonts/`, all OFL: `ShantellSans-Medium.ttf` (google/fonts `ofl/shantellsans`, the weight 500 instance, license `OFL-ShantellSans.txt`), `Bangers-Regular.ttf` (google/fonts `ofl/bangers`, license `OFL-Bangers.txt`), `ComicNeue-Regular.ttf` and `ComicNeue-Bold.ttf` (google/fonts `ofl/comicneue`, license `OFL.txt`), and `NotoSansSymbols2-Regular.ttf` plus `NotoSansSymbols-Variable.ttf` (google/fonts `ofl/notosanssymbols2` and `ofl/notosanssymbols`, license `OFL-NotoSansSymbols.txt`). Anime Ace 2 (Blambot) is free for personal use only, so it is not committed: put `animeace2_reg.ttf` in `fonts/` to use it. Typesetting draws any glyph the lettering face lacks, such as ♡ ♥ ♪ ★, from the first symbol font that has it.

The server needs three model files, which are not committed. Two download directly:

- `models/comictextdetector.pt.onnx` from the zyddnys/manga-image-translator `beta-0.3` release.
- `models/lama_large_512px.ckpt`, the manga-tuned LaMa that manga-image-translator uses as `lama_large`.

Download them with:

```sh
mkdir -p models
curl -L -o models/comictextdetector.pt.onnx https://github.com/zyddnys/manga-image-translator/releases/download/beta-0.3/comictextdetector.pt.onnx
curl -L -o models/lama_large_512px.ckpt https://huggingface.co/dreMaz/AnimeMangaInpainting/resolve/main/lama_large_512px.ckpt
```

The third is `models/manga109-bubble-seg.onnx`, the speech balloon segmenter. The Hugging Face repo `huyvux3005/manga109-segmentation-bubble` ships only PyTorch weights, so export them once with Ultralytics in a throwaway venv: download `https://huggingface.co/huyvux3005/manga109-segmentation-bubble/resolve/main/best.pt`, run `yolo export model=best.pt format=onnx imgsz=1600 opset=17 simplify=True`, and save the result as `models/manga109-bubble-seg.onnx`. The file used here was exported by Ultralytics 8.4.118 and has sha256 `760146a01c3e9f547bc271751bedacd30ae973bfa043dd7761069be7ae0b1336`. Set `YOMIKAE_BUBBLE_MODEL` to another file name in `models/` to use a different Ultralytics segmentation export, such as `kitsumed/yolov8m_seg-speech-bubble`. The input size comes from the model's metadata.

manga-ocr downloads its weights from Hugging Face on first start.

onnxruntime's CUDA provider needs cuDNN, which it finds only after `torch` is imported and `onnxruntime.preload_dlls()` runs. `detect.load_session` does both.

## Pipeline

`pipeline.Engine.process` runs one page through these stages:

1. `detect` runs comic-text-detector. YOLO block boxes go through NMS, then a box that contains two or more other boxes is dropped in favour of them, because NMS keeps a merged block around lines the detector also found one by one. The seg map becomes the per-block text mask, and the DBNet line map decides vertical or horizontal. A block is then cut per bubble, because the detector sometimes boxes the text of two touching bubbles, or of two lobes of one bubble, as one block. The cut follows the light areas (gray 200 or more, text pixels counted as light) that the block's text sits in. Only the text pixels inside the block's own box count, since its padded mask can hold the edge of a neighbour's text. A light area counts as a bubble only when it holds at least 3 times as many pixels as the text inside it. In a toned or gradient bubble, white-edged lettering makes a light sliver around each column that is barely bigger than its glyphs (1.1 to 2.4 times on the reported pages), and every such sliver of a block counts as one area, so the columns stay one block. A bubble area is cut again into lobes from its distance map: a peak becomes a lobe seed at the first level where it stands at least 10% above the level and apart from every earlier seed, so three lobes whose necks sit at different heights are all found. When the distance map shows one lobe, as with a small lobe hung on the side of a big one, the area is cut between its two deepest outline notches, if both are at least 20% of its inscribed radius deep; an outline with more than 5 notches is never cut, so bursts and jagged boxes stay whole. A column of text that runs from one part into the next keeps the block whole. So does text whose parts sit side by side, lined up over at least half their length, less than half a column width apart, since two lobes would put margins and an outline between them. Otherwise each run of text, joined along the reading direction across up to twice the column width measured in each lobe, goes wholly to the part that holds most of it, so a glyph that pokes a few pixels past a lobe boundary does not drag the parts together. A part with at least 5% of the block's text becomes its own block.
2. `balloon` runs the speech balloon segmenter (`models/manga109-bubble-seg.onnx`) on the page, a YOLO segmentation model, at a confidence of 0.25 and NMS IoU of 0.7. Each instance's mask is built only inside its box, from the prototype masks, so the cost stays small on a large page. A block takes the balloon that holds at least half of its text pixels. When two blocks take the same balloon, the model may have merged two touching balloons, so both blocks first try the flood fill below and use the shared balloon only where the flood fill finds no bubble. With `YOMIKAE_BALLOON_DETECT=1`, which is off by default, a balloon that holds less than a tenth of any block's text pixels is one the text detector missed, often a tiny hand-drawn balloon such as ん♡. If its inside is light (median 200 or more), its dark pixels, 2 px inside the outline, become a new block and go to OCR. Such a block is kept only when manga-ocr's mean token probability is at least 0.6 and it is not katakana SFX like ガタッ, because a misread there is translated as dialogue that nobody wrote.
3. `ocr` runs manga-ocr on each block crop. First, when the first or last line of a block of three or more lines is at least 1.5 times as thick as the others, that line is read alone, and if it reads as Latin print (a logo such as "attention!" above Japanese text), the block is cut before it, so the logo keeps its pixels and the translation is not set over it. Blocks that are empty, punctuation, or mostly Latin are dropped here and never touched again. So is short SFX-like kana, unless it sits in a balloon the segmenter found or, failing that, an enclosed speech bubble found by flood fill: short dialogue such as けど or は？ looks the same as SFX, but SFX is drawn on art. So are long readings (20+ tokens) whose mean token probability is under 0.6: that is how manga-ocr reads English print and logos, as fluent-looking Japanese it was unsure of. A block that comes only from the line map or the inverted pass, with less than half of its box under a block-head box, and that sits in no balloon must read with a mean token probability of 0.9 or more and not look like SFX, because those passes also pick up hand-drawn SFX, logo bands and other art.
4. `translate` sends all lines of the page in one call. Within one `context_key`, a line that matches a line of any earlier translated page reuses that translation and is not sent, so a recurring caption reads the same on every page. Lines match after NFKC and after dropping spaces, dots, commas, `、`, `。`, `・`, `ー`, `一`, `っ`, `ッ`, `~`, `～` and `-`, which OCR adds and drops at random. A line with fewer than 2 letters, kana or kanji, such as ？ or え, is always sent, because the model sometimes moves English between lines and one wrong translation of it would spread to every repeat. Lines of 8 or more such characters also match with up to one edit per 8 characters, so 抜く一歩かない still finds 抜く一抜かない. The call carries up to 2 earlier pages of the work as context, only from the 5 pages before this one, because after a jump ahead those pages say nothing about this one. It also carries the work's names, each with a Japanese line it was translated from, so the model can tell which character a spelling belongs to. Names come from three places. Auto names are every `Name-honorific` in the work's translations, kept without the honorific so an honorific the model added never spreads; a line counts for a spelling only when the model wrote it while the list did not already hold it, and of spellings with a similarity ratio of 0.8 or more the one with the most such lines wins. Furigana names come from the small kana printed beside kanji (`ruby.py`, vertical and horizontal), when the translation spells a kanji run of two or more characters from its reading, or a single kanji with an honorific in both languages. User names are set through `/v1/names`. Furigana and user names are stored per work under `cache_dir/names/`, outside the versioned cache, and a user name always wins. Each stored entry is a name (a character) or a term (a technique, place or thing), and terms go in their own `terms` map. The readings found on the page go along as `readings`. Reused lines of this page go along as context too. The reply is a JSON object holding one list, `{"translations": [...]}`, with one string per line in line order, which takes about half the output tokens of an object with an id per line. A reply with the wrong number of strings, or with JSON syntax such as `", "` inside a string, is retried as two halves, recursively, and a single line that still fails is left blank. A line whose translation equals its source, or has more Japanese characters than Latin letters, is retried once in one call for all such lines, then left blank. A blank line keeps its original pixels and is not drawn, and the page is cached with it. The memory and the names come from the pages the server has seen, which it rebuilds from the cache at startup, so they survive a restart.
5. `inpaint` builds the mask per block: the detector's seg mask is snapped to glyph edges with a DenseCRF on a bilateral-filtered copy of the block at 2/3 scale, kept within 0.15 glyph sizes of the seg mask, then dilated by 0.3 x (glyph size + 20) px at that scale, so big lettering and its white outline are covered and small text is not over-masked. Glyph size is the smaller of the column width and the cell size, the square root of the text's ink box area over its character count. The column width alone is not enough: when a vertical block's columns touch, its ink profile never drops, and the whole block reads as one column 2 to 4 times as wide as a glyph (80 px against 20 px on one test page), which grew masks over bubble outlines. Each connected masked region is then filled one of two ways. If the ring of pixels around it is uniform once at most 4 ink strokes entering from outside (a bubble outline, a tail, a strand of hair) are set aside, the region is filled with the ring's median colour and those strokes keep their pixels. Anything else (screentone, hatching, gradients, art) goes to `lama_large`, in bf16 on CUDA (fp32 with `YOMIKAE_LOW_VRAM=1`), on a crop of the region. The crop adds up to one region size of context on each side while it stays within 1024 px, because with less context LaMa smears nearby hatching into dark smudges. A larger region gets 0.4 region sizes of context and its crop is scaled down to 1024 px.
6. `typeset` sets each block in its balloon: the segmenter's mask, eroded by the flood fill's margin when the flood fill below also finds the bubble, else by 7% of the mask's smaller side (3 to 16 px), the rule the flood fill uses. The mask lands on the inner edge of the outline (within 1.3 px on 90% of plain bubbles), so a see-through or stepped box gets its real shape. A caption box found from its outline keeps the outline and its tighter margin instead, and so does a burst the flood fill traces: on bursts the segmenter clips the spikes with its box, leaves holes over big lettering and spills past the outline between the spikes. A block without a balloon of its own grows to its enclosing bubble in the inpainted page (a block sharing a balloon falls back to that balloon when this finds none), then lines English to the bubble's shape (`lining.py`). Breaks are chosen by dynamic programming: a break after a sentence or clause is cheap, a break after a word like "the", "to" or "my" is nearly forbidden, each line's width is pulled toward the bubble's width at that height narrowed toward the ends (a rounded diamond), a short word alone on a line costs extra, and punctuation and `~` stay glued to their word. When the largest size can only end a line on such a word, a size up to 10% smaller that avoids it wins. A bubble tries one word per line and syllable hyphenation (pyphen, `en_US`) only when it can't fit whole at 75% of the page target, so a word is kept whole at a readable size rather than split to fill the bubble. Letters are always drawn at the face's normal width, never squeezed. Below the floor it takes the larger of the two fits, whole words or hyphenated, so a long word in a skinny balloon is split rather than shrunk. All of this happens inside the bubble. The text never spills past the outline, even when that leaves it smaller, except when it fits at no size at all; then it is set at the minimum size, one word per line with a halo, and runs past the outline rather than being cut: the guide prefers a stroked spill to small text, but a neat outline reads better here than bigger text squeezed edge to edge or running onto the art. Hyphenation only splits words too wide for the bubble, of 6 letters or more, at one syllable break at most, with 2 letters before the cut and 3 after, and never splits contractions, hyphenated words (stutters, honorifics) or names (capitalized words that don't start a sentence). By default the text is set in capitals, with lines spaced 1.45 cap heights apart and the block centered on its ink, from the first line's cap top to the last baseline. The block is laid out around the centroid of the bubble interior. A layout more than 5% of the bubble's height away from it counts as a fault, so a size up to 10% smaller at the centroid wins. Points on the way toward the centre of the largest inscribed circle are tried while they stay within that 5%, and that centre itself is the last resort, because in a bubble that tapers or has a tail it sits at the widest row, far from the middle. The page gets one target size, the median of each bubble's largest fitting size (at most 32 px). Each bubble starts at the smaller of its own largest fit and that target. A bubble whose wrapped text covers less than 30% of its interior grows, up to 20% above the target, as long as its text stays centred. A bubble of two or more lines whose text still covers less than 20% of it there keeps growing until it does, up to 50% above the target. One that can't hold the target shrinks as far as it must. Sizes within 10% of each other are then set to the smallest of them, so the page still reads at one size. Shouts sit outside that: a translation of at most 12 words is a shout when its bubble is a spiky burst, or its source glyphs are 1.2 times the page median with a `！` (1.8 times without). A `!!` ending or capitals don't make a shout, since manga puts `！！` on ordinary lines. A bubble is a burst when its outline is both drawn and pointed. Drawn means at least 30% of the pixels within 3 px outside it are ink. A flash or speed-line background with no balloon line fails this, because its lines thin out where they meet the white. Pointed means one of two shapes. A star burst has, among the lobes between its concavities deeper than 4% of its size, at least 3 more pointed lobes (filling less than 0.6 of their chord-by-height rectangle, as a spike does) than round ones (as a cloud's bumps do). A jagged box has a few spikes on mostly straight sides: simplified to within 1.5% of its size, its outline has at least 4 sharp tips and at most 2 sharp notches. A tip is a corner under 130° that turns outward between two inward turns and stands at least 5% of the bubble's size above its neighbours, and a notch is the same corner turned inward. A jagged box also has no more than 2 more round lobes than pointed ones, which rules out clouds. It is measured on the flood fill's outline before erosion, or on the segmenter's mask when the flood fill can't trace the bubble. On the 1546 text blocks the detector finds on the OpenMantra pages, 96 of them hand-labeled as bursts, this finds 69% of the bursts at 89% precision, where the lobe rule alone found 28% at 71%, and it calls 1 of 23 flash backgrounds a burst instead of 5. A shout is set in the shout face at the page size times its glyph ratio, clamped to 1.25 to 1.6, as far as the bubble allows. The clear margin between text and outline is 0.35 of the font size, or the bubble's own erosion when that is larger. Text on art, or with no bubble found, uses the padded block with a contrasting stroke. Blocks never share space: where two blocks' regions overlap (several lines in one frame grow to the same region), each pixel goes to the nearer block, with a gutter between them. When lettered blocks share a double bubble, the bubble is first cut into lobes along the neck, each block keeps the lobes its text sits in, and each lobe is eroded by its own margin. Dark bubbles get white text.

Detection, balloon segmentation, OCR, and inpainting share one GPU lock. Translation runs outside it, at the same time as inpainting, so the next page's detection overlaps this page's LLM call. The lock is released only after PyTorch's cached GPU memory is handed back to the driver, so between pages the server holds the model weights and the CUDA context and nothing else. Before this, PyTorch kept that memory cached for reuse, and a server that started at 3.0 GB of GPU memory held 4.0 GB a few minutes into reading.

## Tests

```sh
.venv/bin/python -m pytest
```

The command in [AGENTS.md](../AGENTS.md) hides the GPU with `CUDA_VISIBLE_DEVICES=`, so the tests run on the CPU next to a running server and LLM.

The tests build synthetic pages with `tools/make_test_page.py` and use the `fake` translator. `test_lm_studio_translates_a_page` uses the real endpoint and skips when it is unreachable.

## Tools

- `tools/make_test_page.py OUT_DIR --count 3` writes synthetic pages and ground-truth JSON.
- `tools/bubble_shapes.py [SEEDS]` scores labeled synthetic bubble outlines (ellipses, tailed and merged bubbles, boxes, notched caption boxes, angular polygons, wobbly ovals, clouds, star bursts, jagged boxes) for burst detection and prints how well bursts separate from the rest.
- `tools/real_bursts.py OPENMANTRA_DIR [LABELS]` runs detection and balloon segmentation on the [OpenMantra](https://github.com/mantra-inc/open-mantra-dataset) pages (CC BY-NC 4.0, not in this repo) and scores burst detection against `tools/openmantra_bursts.json`: hand labels for each text block that is a burst, a flash background, a thought cloud, a plain balloon, text on art, or unsure. Unlisted blocks were only skimmed and count as `rest`. Run it with `python -I`, since it reads a downloaded dataset.
- `tools/translate_file.py OUT_DIR IMAGE...` runs the pipeline on local files without HTTP and prints per-stage timings and bubbles.
- `tools/bubble_proto.py {compare,time,tally} INPUTS... --out DIR --model NAME=PATH.onnx:IMGSZ` compares balloon segmentation ONNX models with the region growing in `typeset.find_region`. `compare` writes a side-by-side mask sheet per page, `blocks.json`, and a `judgments.json` to fill in by hand, `time` measures each model's speed and GPU memory, and `tally` counts the filled-in verdicts by bubble type. Keep its pages outside the repo.
- `tools/gpu_memory.py PROBE [--cap MIB] [--floor MIB]` measures the GPU memory of one pipeline component under a hard allocator cap, and stops at once when the device's free memory falls under the floor.
- `tools/eval_pages.py PAGES_DIR OUT_DIR [--baseline DIR] [--replay SUMMARY]` runs a directory of pages as one work, bypassing the cache, and writes renders, original-vs-render contact sheets (with an earlier run's render in the middle when `--baseline` is given), and `summary.json` with bubbles, skipped blocks, chosen font sizes, and timings. `--replay` reuses an earlier run's translations so typesetting changes compare on identical text. Keep eval pages outside the repo.
